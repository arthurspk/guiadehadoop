## :dart: O guia para alavancar a sua carreira

> Hadoop foi o framework que deu origem ao processamento distribuído em larga escala: HDFS para armazenar petabytes espalhados em centenas de máquinas, MapReduce para processar tudo isso em paralelo e YARN para orquestrar os recursos do cluster. Boa parte do ecossistema que nasceu ao redor dele — Hive, HBase, Pig, Sqoop, Flume, Oozie, ZooKeeper — hoje convive com sucessores mais rápidos como Spark, Trino e os data warehouses na nuvem, que resolvem os mesmos problemas com menos atrito. Ainda assim, Hadoop continua rodando em bancos, telecoms, seguradoras e órgãos públicos que têm clusters on-premises consolidados há mais de uma década, e entender HDFS/YARN/MapReduce é o que torna mais fácil aprender Spark, Trino ou qualquer motor distribuído moderno depois. Este guia reúne documentação oficial, cursos, livros, ferramentas e projetos práticos tanto do Hadoop clássico quanto do ecossistema que o sucedeu, para quem vai manter um cluster legado ou quer entender a fundação sobre a qual o mundo de big data foi construído.

## 📖 Documentação oficial

> Núcleo do Hadoop (HDFS, MapReduce, YARN)

- [Apache Hadoop — Documentação](https://hadoop.apache.org/docs/stable/) — Documentação oficial do projeto: instalação, configuração e guias de cada módulo.
- [Apache Hadoop — HDFS Architecture](https://hadoop.apache.org/docs/stable/hadoop-project-dist/hadoop-hdfs/HdfsDesign.html) — Como o sistema de arquivos distribuído funciona por dentro: blocos, réplicas, NameNode e DataNodes.
- [Apache Hadoop — MapReduce Tutorial](https://hadoop.apache.org/docs/stable/hadoop-mapreduce-client/hadoop-mapreduce-client-core/MapReduceTutorial.html) — Tutorial oficial do modelo MapReduce, o paradigma que originou o processamento de big data em lote.
- [Apache Hadoop — YARN Architecture](https://hadoop.apache.org/docs/stable/hadoop-yarn/hadoop-yarn-site/YARN.html) — Documentação do gerenciador de recursos do cluster, responsável por agendar jobs e alocar memória/CPU.
- [Apache Hadoop — Cluster Setup](https://hadoop.apache.org/docs/stable/hadoop-project-dist/hadoop-common/ClusterSetup.html) — Guia oficial para subir um cluster Hadoop multi-nó do zero.
- [Apache Hadoop — Commands Reference](https://hadoop.apache.org/docs/stable/hadoop-project-dist/hadoop-common/CommandsManual.html) — Referência completa dos comandos de linha (`hdfs`, `yarn`, `mapred`).

> Ecossistema Hadoop (Hive, HBase, Pig, Sqoop, Flume, Oozie, ZooKeeper, Ambari, Ranger, Atlas)

- [Apache Hive — Documentação](https://hive.apache.org/) — Documentação do data warehouse em SQL sobre o HDFS, a porta de entrada mais comum para quem vem do mundo relacional.
- [Apache Hive — LanguageManual](https://cwiki.apache.org/confluence/display/hive/languagemanual) — Referência completa do HiveQL, o dialeto SQL usado para consultar dados no Hive.
- [Apache HBase — Reference Guide](https://hbase.apache.org/book.html) — Guia de referência do banco colunar distribuído inspirado no Google Bigtable, construído sobre o HDFS.
- [Apache Pig — Documentação](https://pig.apache.org/docs/latest/) — Documentação da linguagem de scripts Pig Latin, usada para escrever pipelines de transformação de dados sem Java.
- [Apache Sqoop — User Guide](https://sqoop.apache.org/docs/1.4.7/SqoopUserGuide.html) — Guia oficial da ferramenta que transfere dados entre o Hadoop e bancos relacionais.
- [Apache Flume — User Guide](https://flume.apache.org/FlumeUserGuide.html) — Guia oficial da ferramenta de ingestão de logs e eventos em streaming para o HDFS.
- [Apache Oozie — Documentação](https://oozie.apache.org/docs/5.2.1/) — Documentação do orquestrador de workflows nativo do Hadoop, usado para encadear jobs MapReduce, Hive e Pig.
- [Apache ZooKeeper — Documentação](https://zookeeper.apache.org/doc/current/) — Documentação do serviço de coordenação distribuída usado por HBase, Kafka e o próprio Hadoop para eleição de líder e configuração.
- [Apache Ambari — Documentação](https://ambari.apache.org/) — Ferramenta de provisionamento, gerenciamento e monitoramento de clusters Hadoop via interface web.
- [Apache Ranger — Documentação](https://ranger.apache.org/index.html) — Framework de segurança para gerenciar autorização granular no HDFS, Hive, HBase e outros componentes.
- [Apache Atlas — Documentação](https://atlas.apache.org/#/) — Ferramenta de governança e catalogação de metadados para o ecossistema Hadoop/Spark.
- [Cloudera — Documentação (CDP)](https://docs.cloudera.com/) — Documentação da distribuição comercial mais usada em produção, que embala Hadoop, Hive, HBase, Spark e Ranger em uma plataforma só.

> Motores modernos e sucessores

- [Apache Spark — Documentação](https://spark.apache.org/docs/latest/) — Documentação do motor de processamento em memória que hoje substitui o MapReduce na maioria dos pipelines novos, mas ainda lê e escreve no HDFS.
- [Trino — Documentação](https://trino.io/docs/current/) — Documentação do motor de consultas SQL distribuído (ex-PrestoSQL) usado para consultar Hive, HDFS e outras fontes com latência baixa.
- [Apache Impala — Documentação](https://impala.apache.org/impala-docs.html) — Documentação do motor de consultas SQL de baixa latência para dados armazenados no HDFS e no Hive Metastore.
- [Apache Phoenix — Documentação](https://phoenix.apache.org/) — Camada SQL sobre o HBase, para quem quer consultar um banco colunar do Hadoop com sintaxe relacional.

## 🛠️ Ferramentas

> Núcleo e ecossistema Hadoop

- [Apache Hadoop](https://hadoop.apache.org/) — Framework original de armazenamento (HDFS) e processamento distribuído (MapReduce/YARN) em cluster.
- [Apache Hive](https://hive.apache.org/) — Data warehouse em SQL sobre o HDFS, o jeito mais comum de consultar dados de um cluster Hadoop.
- [Apache HBase](https://hbase.apache.org/) — Banco de dados colunar distribuído em tempo real, construído sobre o HDFS.
- [Apache Pig](https://pig.apache.org/) — Linguagem de scripts de alto nível para escrever pipelines de transformação de dados sem Java.
- [Apache Sqoop](https://sqoop.apache.org/) — Ferramenta para transferir dados entre o Hadoop e bancos relacionais.
- [Apache Flume](https://flume.apache.org/) — Ferramenta de ingestão de logs e eventos em streaming para o HDFS.
- [Apache Oozie](https://oozie.apache.org/) — Orquestrador de workflows nativo do Hadoop, para encadear jobs MapReduce, Hive e Pig.
- [Apache ZooKeeper](https://zookeeper.apache.org/) — Serviço de coordenação distribuída usado por HBase, Kafka e o próprio Hadoop.
- [Apache Ambari](https://ambari.apache.org/) — Provisionamento, gerenciamento e monitoramento de clusters Hadoop via interface web.
- [Apache Ranger](https://ranger.apache.org/) — Framework de segurança e autorização granular para HDFS, Hive, HBase e outros componentes.
- [Apache Atlas](https://atlas.apache.org/) — Governança e catalogação de metadados para o ecossistema Hadoop/Spark.
- [Apache Knox](https://knox.apache.org/) — Gateway de API que centraliza autenticação e acesso seguro a um cluster Hadoop.

> Formatos de arquivo e motores modernos

- [Apache Parquet](https://parquet.apache.org/) — Formato colunar padrão do ecossistema big data, usado por Hive, Spark e data warehouses.
- [Apache Avro](https://avro.apache.org/) — Formato de serialização de dados com schema, muito usado para troca de dados entre jobs Hadoop.
- [Apache ORC](https://orc.apache.org/) — Formato colunar otimizado para o Hive, criado para melhorar performance de leitura no ecossistema Hadoop.
- [Apache Spark](https://spark.apache.org/) — Motor de processamento distribuído em memória, sucessor de fato do MapReduce na maioria dos pipelines novos.
- [Trino](https://trino.io/) — Motor de consultas SQL distribuído para consultar Hive, HDFS e outras fontes com baixa latência.
- [Apache Impala](https://impala.apache.org/) — Motor de consultas SQL de baixa latência para dados armazenados no HDFS.
- [Apache Phoenix](https://phoenix.apache.org/) — Camada SQL sobre o HBase.
- [Apache Airflow](https://airflow.apache.org/) — Orquestrador de pipelines de dados como código, sucessor moderno do Oozie na maioria dos times novos.
- [Cloudera Data Platform](https://www.cloudera.com/products/cloudera-data-platform.html) — Plataforma comercial que embala Hadoop, Hive, HBase, Spark e Ranger prontos para produção on-premises ou na nuvem.

## 🤖 IA na prática

Hadoop é um ecossistema antigo, com muito código legado, jobs MapReduce escritos há anos e documentação espalhada — exatamente o cenário em que um assistente de IA ajuda mais: entender código que ninguém mais mantém e acelerar a migração para motores modernos.

- Cole um job MapReduce em Java ou um script Pig Latin sem comentários e peça para o assistente explicar linha a linha o que ele faz — é mais rápido do que tentar reconstruir a lógica sozinho.
- Peça para reescrever uma consulta HiveQL como uma consulta Spark SQL ou Trino equivalente: é o tipo de tradução mecânica em que a IA acerta a maior parte e só precisa de revisão nos detalhes de performance.
- Assistentes de código como [GitHub Copilot](https://github.com/features/copilot), [Cursor](https://cursor.com/) e [Claude Code](https://code.claude.com/docs/en/overview) ajudam a escrever scripts de administração de cluster (Ambari, Ranger, ZooKeeper) e a depurar erros de configuração do XML do Hadoop (`core-site.xml`, `hdfs-site.xml`, `yarn-site.xml`), que são verbosos e cheios de detalhes fáceis de esquecer.
- O [Databricks Assistant](https://www.databricks.com/product/genie/code) ajuda quem está migrando cargas de trabalho de um cluster Hadoop on-premises para Spark/Databricks, sugerindo o código Spark equivalente a um job MapReduce ou Hive antigo.
- Servidores **MCP** como o [MCP da Databricks](https://github.com/databrickslabs/mcp) conectam assistentes de IA a plataformas de dados reais, permitindo perguntar sobre tabelas, jobs e catálogos em linguagem natural — útil para inventariar o que ainda roda em um cluster Hadoop antes de decidir o que migrar.
- **Limites e boas práticas:** IA pode inventar nomes de tabelas, caminhos do HDFS ou parâmetros de configuração que não existem no seu cluster — sempre valide contra o Hive Metastore e o `core-site.xml` reais antes de aplicar em produção. Um job mal configurado pode processar terabytes ou sobrecarregar o NameNode antes de você perceber o erro, então teste sempre em um diretório de amostra pequeno primeiro. Nunca cole logs com dados de clientes, credenciais do Ambari/Ranger ou configurações de produção em uma ferramenta de IA sem checar a política de privacidade e a LGPD.
